# Booking Bot — Telegram Booking Automation System

*Demo / concept project. All business data is fictional — see [Demo Data](README.md#demo-data).*

## Краткое описание

Telegram-бот и административная система для автоматизации записи клиентов в small-business сфере услуг (тату-студии, барбершопы, бьюти-мастера). Клиент записывается, не выходя из Telegram; владелец бизнеса управляет услугами, мастерами, расписанием и записями из веб-дашборда.

## Проблема

Малый бизнес в сфере услуг обычно принимает записи вручную — через переписку в Telegram, Instagram или по звонку. Это не масштабируется:

- заявки теряются в переписке;
- один и тот же слот случайно бронируют дважды;
- владелец тратит время на согласование расписания вместо основной работы;
- нет единого места, где видно, кто на что записан.

## Решение

Booking Bot закрывает весь цикл записи одним инструментом:

- Клиент проходит полный путь записи в Telegram: услуга → мастер → дата → время → контакты → подтверждение — без единого сообщения администратору вручную.
- Система сама знает, какие слоты реально свободны — с учётом рабочего графика мастера, перерывов, отпусков и уже существующих записей.
- Двойная запись на один слот **структурно невозможна** — это гарантирует сама база данных, а не только код приложения.
- Администратор получает уведомление о каждой новой записи и отмене прямо в Telegram, с кнопками подтвердить/отклонить.
- Все данные — услуги, мастера, расписание, статусы записей — видны и редактируются в одном дашборде, который читает и пишет ту же базу данных, что использует бот.

## Основные функции

- Telegram-бот: меню, каталог услуг и мастеров, полный booking flow, «Мои записи», отмена с учётом дедлайна
- Availability engine — расчёт реально свободных слотов (рабочие часы − перерывы − отпуска − занятые слоты)
- Защита от двойной записи на уровне PostgreSQL (exclusion constraint), а не только в коде
- Admin Dashboard: Overview, Bookings (с фильтрами и действиями), Calendar (день/неделя/месяц), Services/Artists (полный CRUD), Schedule
- Авторизация администратора (Supabase Auth) с проверкой прав на сервере и через Row Level Security — в двух независимых местах, не в одном
- Двусторонние уведомления клиент ↔ администратор
- Идемпотентность и rate limiting на webhook, структурированные логи, валидация всех входных данных (Zod)

## Почему это не просто «бот с кнопками»

Технически интересная часть проекта — не переписка с Telegram Bot API, а то, что происходит вокруг неё:

- **Availability engine** — чистые, юнит-тестируемые функции, которые превращают рабочий график в конкретные доступные слоты с учётом часового пояса бизнеса.
- **Защита от double-booking** — гарантия на уровне базы данных (`EXCLUDE USING gist`), проверенная тестом на реальной гонке двух конкурентных вставок, а не «в коде вроде бы проверяем».
- **Serverless-конversation** — Telegram-бот работает поверх Next.js API routes, которые ничего не помнят между запросами; многошаговый диалог записи держится в отдельной таблице состояния, а не в памяти процесса.
- **RLS как реальная граница прав**, а не декорация — политики проверены живым тестом (не только собственный, но и чужой бизнес недоступен), плюс независимая серверная проверка поверх неё.

## Главный вывод для потенциального заказчика

«Это не просто Telegram-бот. Это готовая система автоматизации записи, которую можно адаптировать под конкретный бизнес» — с базой данных, которая с самого начала спроектирована так, чтобы вырасти в мультибизнес-SaaS, если это понадобится.
